# TancMark Experimental Local Demo

Status: `EXPERIMENTAL_LOCAL_DEMO`.

The local/Docker demo runs the real TancMark text, image, audio, Video Primary, Live, registry/signature, and C2PA code against public synthetic fixtures. It does not return a precomputed success response and it cannot create production ownership or open a production VAULT.

## Availability

**GitHub Codespaces hosted demo currently unavailable.** The hosted attempt entered recovery mode after the image build and a cached rebuild did not become ready within the observed 11 minutes 14 seconds. The failed hosted path is not a release gate. This repository publishes no Codespaces badge, quickstart link, paid prebuild, paid machine, or hosted-startup guarantee.

The demo code remains available for experimental local/Docker use by operators who control the runtime. The `.devcontainer` files are retained as build and security-boundary source, not as a claim that a hosted Codespaces launch currently works. Do not advertise the local measurements as GitHub-hosted startup measurements.

## Local/Docker evidence boundary

The bounded local/Docker fixture, functional, security, C2PA, Live, cleanup, and browser-visibility tests passed in the recorded Linux profile. On the already prepared local Docker snapshot, snapshot verification took 31–36 ms and server start-to-health took 250–270 ms across three repeats. The combined prepared-image lifecycle averaged 292.333 ms with a nearest-rank p95 of 303 ms. These values exclude image construction, GitHub allocation, snapshot transfer, repository synchronization, browser connection, and port forwarding; see `reports/CODESPACES_PREBUILD_LOCAL_FAST_START_20260902.json` and `reports/GITHUB_CODESPACES_HOSTED_DEMO_STATUS_20260902.json`.

Local execution is an experimental operator workflow. Keep port `4173` bound to loopback/private access, use only the generated public fixtures, and preserve the environment allowlist and `DEMO_ONLY` boundary in `.devcontainer/start-demo.sh`.

## Real operations

| Card | Authoritative operation | Negative checks |
| --- | --- | --- |
| Text | Seal, blind recover, registry and ML-DSA test-signature verification | wrong ID, no ID |
| Image | Seal a 512×512 synthetic PNG and run the existing `INFORMED_REFERENCE_PATCH` reader after one frozen lossless transform | wrong ID, no ID |
| Audio | Seal and recover synthetic 44.1 kHz and 48 kHz stereo PCM WAV | wrong ID, no ID, sample count |
| Video | Video Primary seal/recover using FFV1 + PCM Matroska | wrong ID, no ID, frame/PTS/audio integrity |
| Live | Real-time in-stream stamp, RTSP publish, MediaMTX HLS playback, lossless final record and exact verification | wrong tenant, wrong ownership, unsealed injection |
| Registry & Signature | Ephemeral record and ephemeral ML-DSA test key | changed record, wrong signature |
| C2PA | Synthetic PNG inspect, ES256 test sign/embed, reread, verify and tamper detection | no-C2PA, tamper, no VAULT authority |

The video file demo uses a VP9 + Opus WebM preview. The Live player uses VP9 + Opus fragmented-MP4 HLS. Previews are never ownership decision sources. Authoritative video decisions use the lossless output and the exact registry/signature chain.

The image card is a real physical seal/read execution, but it is not presented as blind image recovery: the existing public image reader uses the clean reference patches and expected keyed candidate (`INFORMED_REFERENCE_PATCH`). The UI reports that read mode explicitly. Text is the blind reader in this bounded demo.

## Public fixtures

Only files generated by `runtime/demo/generate-public-fixtures.mjs` are used:

- English and Turkish synthetic text;
- one 512×512 synthetic PNG;
- 10-second 44.1 kHz and 48 kHz stereo multi-tone WAV files;
- one 8-second 640×360 FFV1/PCM video;
- one 16-second 640×360 FFV1/PCM Live source.

Exact dimensions, durations, licenses, deterministic seed, byte sizes, and SHA-256 values are in `fixtures/demo-public/manifest.json`.

## Privacy boundary

Do not paste confidential, personal, or customer text. The optional text field is limited to 2,000 Unicode characters and is neither logged nor persisted. File uploads, filesystem paths, remote URLs, camera, microphone, external stream providers, production registries, production keys, analytics, and telemetry are not accepted.

All results are marked `DEMO_ONLY`. A demo exact result means an ephemeral demo record and test signature were verified; it never means a real owner was verified.

## Measured bounded profile

On the tested real Ubuntu Linux profile, text, image, both audio rates, video, registry/signature, C2PA, cleanup, and browser-visible Live passed 3/3. Live processed 384/384 frames with 0 dropped frames and 0 final backlog. Its three end-to-end durations were 52.612 s, 24.744 s, and 22.631 s; the 16-second source was fed at 1× real time and final physical verification ran after recording finalized.
