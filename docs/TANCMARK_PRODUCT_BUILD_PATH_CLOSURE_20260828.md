# TancMark Product Build Path Closure

The failure was caused by a build-time alias, not by the Live watermark algorithm. The Live worker imported `buildA5StrongL1ByteMatchMask` and `decideFrameEvidence` through `decodeVideo.ts`, while the native product build replaced that module with a stub exporting only `decodeVideo`.

Adding two placeholder exports to the stub would have made bundling progress without restoring the real exact reader. That would be unsafe because `runSignedExactMapVideoOwnershipRoute` uses the canonical decoder and Live automatic final verification uses that route.

The private product packaging records and validation contracts show that `dist-product` is an intentional supported path. The repair therefore preserves `build:product`, keeps the legacy video/audio lab routes disabled, disables the direct video-productization route in the product bundle, removes decoder/helper aliases and moves the pure keyed-L1 frame evidence rules into one shared side-effect-free module. In product mode the canonical decoder and its FFmpeg execution points also require an asynchronous Live-exact internal scope, opened only around the signed automatic Live verification chain. Direct internal invocation outside that scope fails closed. No threshold, registry, signature, tenant or ownership rule was changed.

Measured closure: typecheck, the canonical production build, `build:product`, both server smokes, public tests and generated-code repeatability passed. Both production bundles returned 410 for the legacy video/audio lab routes and served Live local v1. The direct video-productization route returned 410 with ownership, VAULT and final false, and a direct internal canonical-reader invocation outside the signed Live scope was rejected. The repaired `dist-product` bundle processed hash-verified real local H.264 media through the internal Live chain and returned `VIDEO_LAYER_VAULT` with registry and signature verification true. Wrong ID, no-ID before finalization, wrong tenant and unsealed input were rejected; wrong ownership remained zero. Raw expected ID, private map, registry contents and decoder details were absent from API responses and logs.
